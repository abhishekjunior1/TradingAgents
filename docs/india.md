# Indian markets (NSE / BSE)

TradingAgents analyzes NSE and BSE listings with Indian market data, rules and
reasoning. This page covers setup, the CLI, what each data source provides and
costs, what is not available, and the limits of the output. Facts below were
checked on 2026-10-29 and 2026-10-30 against the sources named; rates and rules
change, so re-check them before relying on them.

> Research only. Reports are generated by AI agents from delayed or end-of-day
> data. They are not investment advice, not a prediction, and not research or
> advice from a SEBI-registered research analyst or investment adviser. The tool
> runs in research and paper-trading mode and places no orders; it has no broker
> integration and reads no brokerage credentials.

## Setup

```bash
cd TradingAgents                 # your clone of the repository
python3 -m venv .venv
.venv/bin/pip install --prefer-binary .
source .venv/bin/activate        # puts `tradingagents` on PATH in this shell
```

Choose an LLM provider: an API key (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, ...)
or, for a Claude Pro or Max plan, the `claude_code` provider (README, "Required
APIs"). Nothing else needs a key; `FRED_API_KEY` (free) adds India macro series.

Put Indian defaults in `.env` in the repository folder:

```bash
TRADINGAGENTS_DEFAULT_EXCHANGE=NSE      # bare tickers (RELIANCE) are NSE listings
TRADINGAGENTS_COST_PROFILE=india_equity_delivery
```

## Running

```bash
cd TradingAgents                                        # .env is read from the folder you run in
tradingagents --ticker RELIANCE.NS                      # asks the remaining questions
tradingagents --exchange nse --ticker RELIANCE --analysts market,news,fundamentals --save --no-show
tradingagents --ticker TCS.NS --benchmark "NIFTY IT"    # measure against a sector index
tradingagents --ticker INFY.NS --portfolio book.json    # size against your holdings (INR)
tradingagents --ticker HDFCBANK.NS --vendor news_data=yfinance,alpha_vantage
tradingagents --horizon intraday --exchange nse --ticker RELIANCE --analysts market,news   # a paper plan for one session

tradingagents market                                    # NSE session (IST), indices, India VIX, USD/INR, Brent
tradingagents market --watchlist HDFCBANK,ICICIBANK,SBIN   # plus these stocks, no model called
tradingagents backtest TCS,INFY --exchange nse --start 2026-06-01 --end 2026-09-30
```

`--benchmark` sets what this run's swing decision is measured against. The
memory log stores it with the decision, and whichever later run settles that
decision uses it; other decisions keep their own. An intraday plan has none (it
is scored on its session's bars), so an intraday run neither checks nor uses
the value, and given `--benchmark` the CLI prints a line saying it does not
apply: the run's portfolio risk figures, and off NSE/BSE the market context's
Benchmark row, use the listing's index (NIFTY 50 for an NSE listing, SENSEX
for a BSE one; elsewhere the `benchmark_map` index for its suffix, SPY for a US
listing). A swing run's value is checked before any question is asked or
model called. India VIX, VIX at every term and
the other volatility indices listed in `tradingagents/memory/settlement.py`
(other Cboe indices, MOVE, and the Hang Seng, Nikkei 225, ASX 200 and VSTOXX
ones), which have no return to measure a decision against, and an index Yahoo
keeps no history for are refused. An Indian index with a Yahoo daily history
(see [Tickers](#tickers)) or a `benchmark_map` value is taken as it is, unless
the run is dated more than 30 days back: it then needs a Yahoo close in the 30
days to that date, so a backtest cell before the index's Yahoo history (NIFTY
Financial Services' starts on 2011-09-07) is refused. Any other symbol needs a
Yahoo close in the last 30 days, so Yahoo must be reachable to use one, and is
checked again at the run's own date, still before any model is called: a
past-dated run (`--date`, or a backtest cell) whose benchmark has no close in
the 30 days to that date, such as an ETF listed later, is refused. A backtest
lists a refused cell among its failures. The CLI checks the value at `--date`'s
day before its first question, with at most one Yahoo request, whose prices the
run reuses; a date typed at the prompt is checked when the run starts, and a
refusal then is one line, not a traceback. A refused value stops the run with
the reason and the indices to choose from; the CLI's first check names the
value and where it came from (`--benchmark NIFTY50X: ...` or
`TRADINGAGENTS_BENCHMARK_TICKER NIFTY50X: ...`). The agents are told this run's
benchmark and the report header names it (`benchmark NIFTY IT (^CNXIT), set for
this run`); the market tools still measure relative performance against the
listing's own exchange index (NIFTY 50 for an NSE listing, SENSEX for a BSE
one) and the closest sector index. NIFTY 50 or SENSEX analyzed as the ticker
is, by default, measured against itself, so its alpha is zero: its reflection is
told to judge the raw return, and a backtest leaves such cells unscored.

`tradingagents market` gives each series the date of its own last close, and
`--date YYYY-MM-DD` shows an earlier day (never one after today on the
exchange's clock). Before a special session it names it, then the next regular
session: `Next session: Sun 08 Nov 2026, Muhurat trading (Diwali), 14:20-15:30
IST (pre-open from 14:05).` With no terminal (a pipe, cron, Claude Code's Bash
tool) its tables are printed as markdown text; at a terminal too narrow for a
table, the table narrows only as far as its values allow, else shows each row as
label and value lines, so no date or price is cut.

`market --watchlist` also takes the name of a list in your watchlists file
(`--watchlist banks`; see [Watchlists](#watchlists)); a name the file does not
have is read as a ticker, so define the list before using its name. `backtest
--watchlist` takes list names only and refuses an unknown one, naming the lists
it found and the file it checked; give symbols as the tickers argument instead
(`backtest TCS,INFY`).

`python -m cli.main` works in place of `tradingagents` from the source folder.
From Python, `TradingAgentsGraph(...).propagate("RELIANCE.NS", "2026-10-28")`
(see `main.py`).

`--horizon intraday` plans one session instead of rating the position: an
intraday (MIS) paper plan that exits by your broker's square-off time, counts
intraday charges and is scored on that session's 5-minute bars. In Claude Code,
`/day-trader RELIANCE` runs it for one stock. See [docs/intraday.md](intraday.md)
for the session rules, broker square-off times, charges, leverage and Yahoo's
intraday limits.

US tickers after midnight IST: until New York's own midnight (09:30 IST, 10:30
IST while New York is on standard time) New York is still on the previous day,
and its regular session trades until 01:30 IST (02:30 IST in US winter). The
CLI's default date for a US ticker is then New York's, and a run dated it is
treated as a run dated today, not a past one: it gets the live company profile
and upcoming events, news through New York's midnight (undated stories
included) and live web pages, and its lessons are not filtered as a backtest's
are.

| `RELIANCE.BO`, `BSE:RELIANCE`, `BOM:RELIANCE` | `RELIANCE.BO` | BSE, by symbol |
| `RELIANCE` with `--exchange nse` | `RELIANCE.NS` | bare symbols need an exchange |
| `M&M`, `BAJAJ-AUTO` with `--exchange nse` | `M&M.NS`, `BAJAJ-AUTO.NS` | |

| `BANKNIFTY`, `NIFTY BANK` | `^NSEBANK` | |

After an exchange prefix, an NSE series or a listing suffix (`-EQ`, `.NS`, `.BO`)
is dropped and the prefix decides the exchange: `NSE:SBIN-EQ` and `NSE:SBIN.NS`
are both `SBIN.NS`.

Also mapped: NIFTY Next 50, 100, 500, Auto, Pharma, FMCG, Metal, Energy, Realty,
PSU Bank, Infrastructure, Consumption, MNC (`tradingagents/markets/india.py`).
Yahoo lists NIFTY Media, Midcap 100, Smallcap 100, Private Bank, Healthcare and
Oil & Gas with almost no history, so they are named but never used for returns,
and `--benchmark` refuses them.

### Watchlists

Keep them in `~/.tradingagents/watchlists.json` (or `TRADINGAGENTS_WATCHLISTS_FILE`):

```json
{"banks": ["HDFCBANK", "ICICIBANK", "SBIN", "KOTAKBANK"], "it": ["TCS", "INFY", "HCLTECH", "WIPRO"]}
```

In `tradingagents market`, a watchlist row gives the stock's last close and that
close's date, its changes over 1 day to 3 months, and its return against its
exchange's index (NIFTY 50 for NSE, SENSEX for BSE) over the last 21 and 63
sessions both have; when the index has no close yet for the stock's latest
session, those columns stop at the last close both have and say so
("(to 27 Oct)"). The market context the agents get measures a stock against
its exchange's index (NIFTY 50 or SENSEX) and its closest sector index the same
way, over 21, 63 and 250 sessions, and names the last close both have when
either series stops first. An entry with no data, or one Yahoo cannot be asked
for, such as `USD/INR` or a name with a space (`TATA MOTORS`), gets its own
"unavailable" row with the reason ("did you mean USDINR=X?" for the pair), and
the other rows still show; write the rupee pair `USDINR` or `USDINR=X`.

No index constituent lists ship with the tool: they change at every rebalance.
NSE publishes them (for example `ind_nifty50list.csv`); niftyindices.com permits
personal, non-commercial use, and NSE's website terms prohibit automated
collection, so download a list by hand if you want one.

### Portfolio file (INR)

```json
{
  "cash": 500000, "currency": "INR",
  "positions": [
    {"ticker": "RELIANCE.NS", "quantity": 100, "average_price": 1200, "acquired": "2025-01-15", "sector": "Energy"},
    {"ticker": "TCS", "quantity": 50}
  ]
}
```

With a portfolio, the trader, risk and portfolio agents also get computed
figures: value in INR; per holding, volatility and maximum drawdown over the last
year (or over the sessions there are, which they state), beta and 1-year return
against the run's benchmark (on an intraday run, the listing's index: NIFTY 50
or SENSEX, else the `benchmark_map` index, SPY for a US listing, whatever
`--benchmark` or `TRADINGAGENTS_BENCHMARK_TICKER` says), unrealized P/L when
`average_price` is given, and an estimated capital-gains tax when `acquired` is
too; the book's sector exposure and concentration; a sizing reference for the
analyzed stock (risk `risk_per_trade_pct`, default 1%, with a 2 x ATR(14) stop,
capped so that the position after the trade, any holding of it included, stays
within `max_position_pct`, default 20%); and estimated charges.
During an NSE/BSE session, a holding that has traded that day is valued at its
latest price, and its volatility, drawdown, beta and return, and the stop's ATR,
use closes through the last complete session.

- **Lots.** A stock can be listed as several lots, each with its own `acquired`
  date (yours, YYYY-MM-DD): each gets its own holding period and tax, and the
  lots are added up for the totals, concentration and the sizing cap. A
  past-dated run, such as `backtest --portfolio` with today's book, leaves out
  the lots acquired after its date (from the holdings the agents see, the risk
  figures and the Day Trader's paper-sizing capital), and the risk figures say
  how many. A run dated today, by the analyzed listing's day (New York's for a
  US ticker after midnight IST, as above), counts every lot in the file, the
  book being today's, and estimates tax on a sale now: every NSE/BSE lot's
  holding period is counted to today's date in India, even on a US run dated by
  New York's day. The same book at the same moment then gets the same term and
  tax whichever ticker is analyzed, and a lot reaches long-term at India's
  midnight. A lot dated after today in India is counted too, with no holding
  period or tax estimated ("purchase date ... is after ... (today in IST)"). A
  past-dated run counts holding periods to its own date.
- **Cash.** Negative cash is shown as money owed, with no cash share. Cash in a
  book with no `currency` is taken to be in its holdings' currency (with no
  holdings, the analyzed stock's) and is marked "taken as INR".
- **Currencies.** Yahoo prices NSE/BSE listings in INR, a plain US listing in USD
  and a crypto pair in the currency or coin it is quoted in (BTC-INR in INR,
  ETH-BTC in BTC), whatever the book's `currency` says. Any other holding (a
  London, Tokyo or Hong Kong listing, a future, a forex pair) is taken to be
  priced in the book's `currency`, since no exchange rate is applied, so an INR
  book counts VOD.L's price in pence as rupees, and a GBP book counts it as
  pounds, 100 times too high. INR cash or NSE shares held with US shares (bought
  under LRS), with BTC-USD or with ETH-BTC make a book in several currencies; it
  gets no totals, concentration or sector exposure, and its sizing reference is
  "n/a" with the reason, as is that of a book with no `currency` that holds one
  of those other listings. BTC-INR keeps an INR book in one currency. A pair
  quoted in a coin is never sized against a rupee or dollar book. Prices per
  unit (average price, last close or latest price, the sizing reference's entry
  and stop) keep six significant digits and at least two decimals, as the
  market tools show them: 0.0289 BTC, or XRP-BTC's 0.000016133 BTC. Totals,
  values and P/L in a coin are still shown with two decimals.
- **Sizing reference.** It is given only for an NSE/BSE stock, a US listing or a
  crypto pair priced in the book's currency, so an INR book gets one for an
  NSE/BSE stock; another stock, or an index, gets "n/a" and the reason.

## Indian market rules the agents use

- **Sessions (IST).** Pre-open 09:00-09:15; regular 09:15-15:30. From 3 Aug 2026,
  stocks with derivatives trade continuously to 15:15, then in a closing auction
  15:15-15:35; from 7 Dec 2026 the auction runs 15:30-15:40. Post-close ends 16:00,
  and only then is a day's close final. Sources: SEBI circulars of 16 Jan and
  15 Oct 2026; NSE/CMTR/75479, 76187. Agents are told only the rules in force on
  the analysis date. On a special session that keeps other hours (Muhurat
  trading, Sun 8 Nov 2026: pre-open 14:05-14:20, trading 14:20-15:30), a run
  dated that day is told its hours as well as the usual ones.
- **Holidays.** The 2026 NSE list (NSE/CMTR/71775, 72260; BSE's matches) and the
  special Sunday sessions of 1 Feb (Union Budget) and 8 Nov (Muhurat) are in
  `tradingagents/markets/india_calendar.py`. Add each new year's list when the
  exchanges publish it (December); a year not listed is reported as not covered,
  only weekends count as closed, and Yahoo's filler rows for that year's
  holidays are read as sessions.
- **Also given:** T+1 settlement; price bands and dynamic bands; market-wide
  circuit breakers (10/15/20%); SEBI LODR results deadlines (45 / 60 days); the
  RBI MPC schedule for 2026-27 (RBI press release of 23 Mar 2026); the Union Budget
  date; and the India-specific drivers to weigh (RBI, Budget, SEBI, FII/DII flows,
  the rupee, crude). Every agent is told to cite each claim's tool and date, mark
  assumptions, and report missing data instead of estimating it.

### News, insider trades, statements and corporate actions

- **Global news** for an NSE/BSE listing comes in two sections. *India*: Yahoo
  searches for `rupee`, `RBI` and `India` (`global_news_queries_india`), run as
  exact searches (`global_news_india_fuzzy: False`), keeping only stories whose
  title or summary names a term in `global_news_india_terms` (whole words, any
  case: India, Indian, SEBI, Sensex and the like), or two of
  `global_news_india_weak_terms` (rupee, RBI, Nifty, NSE, BSE), or that Yahoo
  tags with an `.NS`/`.BO` listing, an Indian index or the rupee. A weak term
  alone also names things outside India (the Pakistani rupee, Raiffeisen Bank
  International, Retail Banker International), so it needs a second India
  signal; untagged headlines that say only "RBI", such as one about an RBI rate
  rise in Yahoo's results on 2026-10-29, are dropped as a result. *Global*: the usual `global_news_queries`, unchanged. The
  article limit is split between them (India takes the odd one; a share one
  section leaves unused goes to the other). A section that shows nothing says
  whether the limit left it no room, the searches above already found its
  stories, or its search kept none; an empty Global section over a window
  Yahoo's search does not reach says the news is unavailable, not that there was
  none. Yahoo carries little India news: on 2026-10-29 its fuzzy search
  answered "RBI monetary policy repo rate" with US stories, and exact searches
  for "Sensex", "Nifty 50" and "Indian stocks" returned nothing from that week.
  When the India section is empty it says so, and that RBI policy, the rupee,
  SEBI, the Union Budget and FII/DII flows must be reported as unavailable.
  With [Agent-Reach](agent-reach.md) switched on (optional), news comes from
  Exa's web search first, Yahoo being the fallback, and the India section is
  searched with multi-word topics that suit Exa (`agent_reach_india_queries`: RBI
  policy, Nifty and Sensex, FII/DII flows, the rupee, inflation, SEBI, the Union
  Budget, crude). Exa's dates come from the pages, so it is most reliable on runs
  dated today; when nothing it finds is dated in the window, Yahoo answers.
  Emptying `global_news_queries_india` keeps both sections: Yahoo's India
  section then says no India searches are configured and that those drivers
  must be reported as unavailable, and Agent-Reach still searches
  `agent_reach_india_queries`.
- **Company news** is often missing: on 2026-10-29 Yahoo had no article tagged
  RELIANCE.NS, and the news tool then reports company news as unavailable.
- **News dates.** For an NSE/BSE listing, Yahoo's and Exa's news windows, and
  the Reddit and StockTwits ones, count India's days: they end at the midnight
  IST that ends the run date, so a past run reads nothing from the next Indian
  morning.
- **Insider transactions.** Yahoo states no currency for its insider rows. For
  RELIANCE.NS and INFY.NS on 2026-10-29, their per-share prices were about
  1/USDINR of the INR close on the same day. When the prices do not fit the
  stock's own closes over those dates, the tool adds a note that they are not
  rupee amounts. The closes from a week before the first trade to the last are
  used whatever the listing did after them, with no staleness test, and never
  read past the run date: a listing whose Yahoo history stops or pauses during
  or after the trades (suspended, or back from a suspension) is checked against
  the closes it has then. They come from the price tools' 5-year download when
  it holds those dates. A listing counts as having no closes only when Yahoo has
  none over those dates, and only then (or when they cannot be retrieved) is a
  BSE listing checked against the NSE listing under the same symbol (Yahoo has
  no daily history for RELIANCE.BO). When there are no
  closes to check against, the note still says that Yahoo states no currency and
  not to assume rupee amounts, and it says whether Yahoo had no closes then or
  they could not be retrieved (a rate limit or an outage). Indian
  insider trades are disclosed on NSE/BSE under SEBI's insider-trading (PIT)
  regulations, which this tool does not read.
- **Statements.** Each Yahoo statement is headed with its source, the currency
  the company reports in (Yahoo's `financialCurrency`) and its unit: full units,
  not thousands, millions or crores, except per-share figures such as EPS. That
  currency need not be the listing's: INFY.NS quotes in INR and reports in USD,
  so its Diluted EPS of 0.80 is dollars, and the header says to convert before
  comparing. When Yahoo does not give the currency, the header says so, or,
  when Yahoo's company profile did not load (a rate limit or an outage), that
  the currency could not be retrieved; either way it says not to assume the
  listing's. Quarterly columns that are not consecutive quarters
  are flagged: Indian companies publish a balance sheet only with their
  half-year and annual results (SEBI LODR), so RELIANCE.NS's quarterly balance
  sheet had columns six months apart on 2026-10-30, and Yahoo's quarterly data
  can skip a quarter.
- **Quarterly cash flow.** SEBI LODR requires a cash-flow statement half-yearly,
  with the half-year results, and on 2026-10-29 Yahoo had no quarterly one for
  RELIANCE.NS. When no vendor has one for an NSE/BSE company listing,
  `get_cashflow(freq="quarterly")` says why and points to `freq="annual"`; when
  Yahoo does serve one, it is passed through. An index (NIFTY 50, SENSEX) has
  no statements and gets the usual no-data message.
- **Corporate actions.** Dividends are on Yahoo's present-day share basis, the
  basis of its prices too: Yahoo divides a dividend paid before a split, bonus
  issue or share consolidation by its ratio, so on 2026-10-30 Reliance's ₹10 of
  August 2024 showed as 5.00, after the 1:1 bonus of 28 Oct 2024, while a
  consolidation (fewer, larger shares) raises the amounts paid before it. A run
  dated today is told this and given the splits and bonus issues to multiply
  back by. A past-dated run is not shown those after its date, so its amounts
  can be below the ones declared (after a later split or bonus issue) or above
  them (after a later consolidation); it is told that either can happen, in the
  same words whatever came after its date, so the label gives nothing away.
  Yahoo's results calendar goes only to a run dated today: a
  results date that has passed is labelled the latest, not the next (Yahoo keeps
  it until it lists the next one: TCS.BO still showed 8 Oct on 2026-10-30), and
  one on the run date says the results may not be out yet.

Choose vendors per category with `--vendor category=vendor` or the
`data_vendors` config (`core_stock_apis`, `technical_indicators`,
`fundamental_data`, `news_data`, `macro_data`, `market_context`,
`corporate_actions`); a vendor that fails yields a "data unavailable" notice,
never an invented figure. A `--vendor` chain must leave no tool of its category
without a vendor that can run: `fundamental_data=sec_edgar` needs a fallback
such as `sec_edgar,yfinance`, `news_data=agent_reach` needs
`agent_reach,yfinance`, and Alpha Vantage counts only when
`ALPHA_VANTAGE_API_KEY` is set. Otherwise the run stops before it starts,
naming the tool and a fix.

### Not integrated, and why

| Source | Status |
|---|---|
| NSE / BSE official feeds | Licensed. NSE Data & Analytics publishes tariffs (end-of-day about ₹1 lakh a year per segment; real-time vendor feeds tens of lakhs a year; check NSE's tariff PDFs). NSE's website terms prohibit automated data collection, so nothing here scrapes nseindia.com or bseindia.com. |
| Broker APIs (Zerodha Kite Connect ₹500/month, Upstox, Dhan ₹499/month, Angel One SmartAPI) | Need a brokerage account and credentials, which this research tool does not use. Kite's terms forbid redistributing its data. |
| EODHD, Twelve Data, Financial Modeling Prep | Paid for Indian coverage (EODHD from $19.99/month personal use; Twelve Data's India plan from $329/month; FMP's global plan $139/month). Could be added as vendors. |
| Indian news RSS (Economic Times, Mint, Business Standard, BusinessLine, Moneycontrol) | Not added: their feed terms could not be verified, and Business Standard's terms bar automated access. Yahoo news and India-focused news searches are used instead, and they carry little India news (see above); the optional Agent-Reach web search is another route ([docs/agent-reach.md](agent-reach.md)). |

**Not available at all:** FII/DII daily flows, promoter holdings and pledges, F&O
open interest, exchange announcements, a stock's own price band, live quotes.
The agents are told these are unavailable. SEBI PIT insider disclosures are not
read either; the agents are told so only when Yahoo's insider prices do not fit
the stock's closes or cannot be checked against them. Quarterly cash-flow
statements are often missing (see above).

| DP charge | ₹15.34 per sell (incl. GST) | none | a discount broker |

Capital gains on listed shares (`india_listed_equity`): 20% short-term (held up
to 12 calendar months, so a sale on the anniversary, such as 15 Jun 2023 to
15 Jun 2024, is still short-term and long-term starts the day after), 12.5%
long-term above ₹1.25 lakh a year (Income-tax Act 2025 s.196 / s.198, formerly
s.111A / s.112A; unchanged by Budget 2026); surcharge and cess not included.
Override any field in config, e.g.
`cost_overrides={"brokerage_rate": 0.001, "brokerage_cap": 20}` or
`capital_gains_overrides={"long_term_exemption": 0}`, or set `cost_profile` to
`none`. `long_term_after_months` must be a whole number of months (`12.0` counts
as `12`). These settings are checked when the graph is built, as
`intraday_cost_overrides` is, for every run: an unknown profile or rules name,
an unknown field, or a `long_term_after_months` that is not a whole number
(12.5) stops the run before any model is called, with the reason, which the
CLI prints as one line rather than a traceback; a `TRADINGAGENTS_COST_PROFILE`
that names no profile stops it earlier, at start-up. Intraday
mode sizes and scores its paper plans with its own settings,
`intraday_cost_profile` (default `india_equity_intraday`) and
`intraday_cost_overrides`, not `cost_profile` and `cost_overrides`
([docs/intraday.md](intraday.md#charges)).

## Paper trading, and why no public arena

Everything here is paper: a swing decision goes into the local memory log, and an
intraday plan is scored there on its session's bars. Decisions on NSE/BSE
listings are never sent to AlphArena, the optional public paper-trading arena
for US stocks ([docs/arena.md](arena.md)); `tradingagents arena close` refuses
them too. SEBI's press release No. 27/2024 (4 Nov 2024) says apps "offering
virtual trading services or paper trading or fantasy games to the public based
on stock price data of listed companies" violate the Securities Contracts
(Regulation) Act and the SEBI Act, and its circular of 24 May 2024 bars
exchanges and intermediaries from sharing real-time price data with third
parties, citing such platforms. This is not legal advice.

## Environment variables

| Variable | Purpose |
|---|---|
| `TRADINGAGENTS_DEFAULT_EXCHANGE` | `NSE` or `BSE` for bare tickers |
| `TRADINGAGENTS_BENCHMARK_TICKER` | index swing decisions are measured against, for those recorded while it is set (default: NIFTY 50 for NSE listings and indices, SENSEX for BSE); checked before a swing run as `--benchmark` is. An intraday run neither checks nor uses it: its portfolio risk figures, and off NSE/BSE its market context's Benchmark row, use the listing's index, as do `tradingagents market` watchlist rows off NSE/BSE while `TRADINGAGENTS_DECISION_HORIZON` is `intraday` |
| `TRADINGAGENTS_COST_PROFILE` | `india_equity_delivery`, `india_equity_intraday` or `none`, any case; another name stops the run at start-up, naming the variable, as `TRADINGAGENTS_INTRADAY_COST_PROFILE` does |
| `TRADINGAGENTS_RISK_PER_TRADE_PCT`, `TRADINGAGENTS_MAX_POSITION_PCT` | sizing reference |
| `TRADINGAGENTS_WATCHLISTS_FILE` | watchlists JSON |
| `TRADINGAGENTS_DECISION_HORIZON`, `TRADINGAGENTS_INTRADAY_SQUARE_OFF` | `intraday` for a one-session paper plan; your broker's MIS square-off, HH:MM IST (default 15:10; [docs/intraday.md](intraday.md)) |
| `TRADINGAGENTS_INTRADAY_COST_PROFILE` | charges for intraday plans: `india_equity_intraday` (default) or `none`; per-field overrides with `intraday_cost_overrides` ([docs/intraday.md](intraday.md#charges)) |
| `TRADINGAGENTS_AGENT_REACH` | news from Exa's web search first ([docs/agent-reach.md](agent-reach.md)) |
| `FRED_API_KEY`, `ALPHA_VANTAGE_API_KEY` | optional data vendors |

Keys belong in the environment or `.env`; none is written to reports or logs.
